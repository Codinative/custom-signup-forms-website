# .dc.html → components

## 1. Read the artboard
- Designs: `/Users/macbook/Documents/Arham Asjid/apps/Custom Signup Forms/Code/website-redesign-handoff/design/`. Route ↔ file map: `scripts/visual/pages.mjs`.

- Before coding, write a section table: desktop section → phone counterpart, with copy differences and parts that are hidden on each.

## 2. Shared design classes → build
| design | build |
|---|---|
| `.disp` / `.mono` / `.eyebrow` / `.lede` / `.body` | global utilities of the same name in `app/globals.css` |
| `.btn .btn-sm .btn-primary .btn-white .btn-ghost .btn-outline .btn-violet` | `<Button variant size>` (heights other than 40/48/54 go in a page class via `className`) |
| `.tag` + inline bg/colour | `<Tag tone>` |
| `.ph` | `<PlaceholderBox>` |
| `.frame` `.frame-bar` `.dot` | `<BrowserFrame url? barOnPhone?>` (see ARCHITECTURE §4) |
| `.check` + svg | `<Icon name="check" className={…}>` |
| inline `<svg>` | `<Icon name>` from the registry (exact paths, `strokeWidth` as in the design) |

## 3. Inline style → CSS Module
- Copy declarations 1:1 into a camelCase module class. px stays px; shorthands stay as written (`padding:88px 120px 56px`).
- Do not add properties the design does not set. No line-height in the design means `normal`; don't "fix" it.
- Sections: full-bleed background on the outer element; inner content `max-width:1440px; margin-inline:auto` plus the design's padding.
- Colours: use the `var(--…)` token when the hex matches one in `app/globals.css`; otherwise the literal value.
- Text with `text-wrap:balance|pretty` keeps it. `&nbsp;` → `{" "}`; `<br>` → `<br />`; apostrophes as `&apos;` or `’` exactly as in the design (lint: react/no-unescaped-entities).

## 4. Responsive (desktop-first)
- Base styles = desktop artboard.
- `@media (max-width: 1279px)`: fluid tablet rules. Side padding `var(--pad-x-tablet)` (32→48px), 4-col → 2-col, 3-col → 2 or 3 by fit, feature rows side by side to 1024 then stacked text over screenshot (`@media (max-width: 1023px)`).
- `@media (max-width: 767px)`: phone artboard values exactly (20px gutter unless the design says otherwise).
- Different copy or structure on phone: render both, `className="onlyDesktop"` / `"onlyPhone"` (globals). Never two `h1`s: put both variants as spans inside one heading.
- Fixed pixel widths from the desktop (e.g. `max-width:470px`) stay; widths that would overflow on small screens get `max-width:100%`.
- Tables and code: wrap in a container with `overflow-x:auto` when content can exceed the viewport.

## 5. Images
- Originals live in `public/images/` (copied from the handoff `assets/`; the storefronts crop is `storefronts-crop.png`, 860×580).
- `next/image` with string `src="/images/<file>"`, explicit `width`/`height` (intrinsic), a real `alt` describing the screen, and a `sizes` that matches the rendered width, e.g. `sizes="(max-width: 767px) calc(100vw - 40px), (max-width: 1279px) 90vw, 1200px"`.
- The custom loader serves WebP variants generated by `scripts/images/optimize.mjs`. Never use raw `<img>`.
- `priority` only for the above-the-fold hero screenshot.

## 6. Links
- `href="#"` in designs → targets from the link map in `docs/ARCHITECTURE.md`. Internal: `next/link` with a trailing slash. External: `target="_blank" rel="noopener"`.

- No value invented; no design value dropped; no file over 300 lines.
- `npm run typecheck` and `npm run lint` are clean for your files. No screenshots: testing happens later.
